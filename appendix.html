B · UML 速查

七种 UML 图的用途与符号

全书理论基石共使用 7 种 UML 图。下表给出每种图的用途、核心符号、出现章节，作为读图与画图的快速索引。

① 用例图 Use Case

用途：刻画参与者与系统功能（需求层）。
符号：小人=参与者；椭圆=用例；连线=关联；<⟨include⟩/⟨extend⟩=包含/扩展。
见：第1章（智能体能力映射）、第3章（需求建模）。

② 类图 Class

用途：描述领域对象及其静态结构与关系（设计层）。
符号：三层矩形=类；"+/-"=可见性；实线三角=泛化；实线=关联；虚线三角=依赖。
见：第3章（领域类）、第5章（知识对象）。

③ 活动图 Activity

用途：展示业务流程或算法步骤的流转（流程层）。
符号：圆角矩形=动作；菱形=判定；粗横线=分叉/汇合；箭头=控制流。
见：第2章（规划流程）。

④ 时序图 Sequence

用途：按时间顺序展示对象间消息交互（动态层）。
符号：矩形条=生命线；箭头=消息；虚线返回=reply；方框=激活期。
见：第5章（RAG 调用）、第7章（多智能体协作）。

⑤ 状态图 State

用途：描述对象在生命周期内的状态变迁（行为层）。
符号：圆角矩形=状态；箭头=迁移（事件[条件]/动作）；实心圆=初态；牛眼=终态。
见：第9章（系统生命周期）。

⑥ 组件图 Component

用途：展示系统物理构件及其依赖（架构层）。
符号：带两个小矩形的矩形=组件；接口半圆=提供；套筒=需求；虚线=依赖。
见：第4章（智能体架构）、第8章（低代码应用）。

⑦ 部署图 Deployment

用途：描述软硬件节点与构件的物理分布（运行层）。
符号：立方体=节点（服务器/设备）；连线=通信；内部构件=部署关系。
见：第6章（多模态部署）。

说明：本速查仅列课程用到的 7 种图；UML 2.x 还包含对象图、组合结构图、包图、交互概览图、通信图、定时图等，超出本教材范围。
C · Coze 操作清单

各章上机实验分步手册汇总

把第1–9章"上机实验"的关键操作收敛为可执行的核对清单（Checklist）。上机前逐项打勾，可保证实验不漏步。

第1章 · 创建你的第一个智能体

  1. 登录 Coze，进入"我的空间 → 创建智能体"。
  2. 填写人设与回复逻辑（角色、语气、约束），可试运行。
  3. 配置开场白与用户问题建议，提升首屏体验。
  4. 在"预览与调试"中多轮对话，观察感知—决策—行动循环。
  5. 发布到体验版，截图保存对话样本。

第2章 · 智能体项目的立项与可行性自查

  1. 用一句话写清目标用户与待解决问题。
  2. 对照技术 / 经济 / 操作 / 法律四维度各写 1 条可行性结论。
  3. 用MVP思路界定第 1 版范围边界，写入"不做清单"。
  4. 明确可量化的成功指标（如准确率、响应时长）。

第3章 · 对话式需求定义

  1. 与智能体对话，口头描述你想让它完成的任务。
  2. 将其转化为用户故事："作为…，我想…，以便…"。
  3. 区分功能需求（做什么）与非功能需求（多快/多安全）。
  4. 画出核心用例图（参与者 + 主要用例）。

第4章 · 为智能体装配能力

  1. 在"插件"市场添加所需能力（如天气、搜索、计算器）。
  2. 用工作流编排多步逻辑，替换纯对话流处理复杂任务。
  3. 设计人设与回复逻辑作为"大脑"，约束输出风格。
  4. 绘制组件图呈现"人设 / 插件 / 工作流 / 知识库"的关系。

第5章 · 知识库与提示词工程

  1. 新建知识库，上传文档或表格并等待切片向量化。
  2. 在提示词中写入角色 / 任务 / 约束 / 输出格式四要素。
  3. 开启RAG，观察回答是否引用知识库内容。
  4. 用上下文工程思路调优：系统提示 + 记忆 + 检索结果如何组合。

第6章 · 记忆与多模态

  1. 用变量保存会话级临时信息（记事簿）。
  2. 用数据库保存结构化共享数据（共享表）。
  3. 用记忆库沉淀长期用户偏好（长期记忆）。
  4. 添加图像/音频插件，验证多模态输入可被理解。

第7章 · 复杂工作流与多智能体

  1. 使用批处理 / 循环 / 代码等逻辑节点构建业务流。
  2. 将通用流程嵌套进更大工作流，提升复用。
  3. 拆分子任务给多个智能体，定义协作时序。
  4. 绘制时序图核对消息顺序与职责边界。

第8章 · 低代码应用与 AI 编程

  1. 在低代码画布拖拽页面组件，绑定数据源。
  2. 为按钮等元素绑定事件，调用智能体或工作流。
  3. 用AI 编程生成页面片段，再人工微调。
  4. 确认应用形态区别：智能体（对话）vs 低代码应用（界面）。

第9章 · 发布、测试与评测

  1. 选择发布渠道，使用热更新快速迭代。
  2. 设计功能 / 边界 / 安全三类测试用例并执行。
  3. 从正确性 / 安全性 / 体验维度做自动评测。
  4. 整理Capstone项目交付物：智能体 + 文档 + 演示。

H.5　设计原则与设计模式：SOLID / GoF 23

原则/模式要点智能体映射
高内聚低耦合模块内部紧密相关、对外依赖松散一个 Agent 只干一类事（高内聚）；Agent 间经明确接口/协议通信（低耦合）

H.6　面向服务与微服务：SOA / API / 业务能力

原版对应：ch10 应用架构设计（分层/MVC/微服务）、ch13 面向服务设计（单体 vs 微服务、系统操作、业务能力、API）。

  • 单体 vs 微服务：单体部署简单但难扩展；微服务按业务能力拆分、独立部署。智能体系统天然"微服务化"——每个 Agent = 一个能力服务。
  • 定义系统操作：从用例/外部请求识别系统操作，再分配给服务并定义 API。等价于"把用户意图拆成 Agent 可调用的工具/接口"。
  • API 设计：服务通过 API 暴露功能；智能体的工具调用（Function Calling / MCP）就是它的"API 契约"。
经典 ↔ 智能体"每个智能体 = 一个业务能力 / 一个微服务"是理解多智能体架构最稳的心智模型。

H.8　非功能需求与性能/可用性架构

原版对应：附录A 非功能性需求分析与设计（性能、可用性、高可用架构）。
